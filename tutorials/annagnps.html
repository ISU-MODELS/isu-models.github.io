AnnAGNPS

A first successful run of the Annualized Agricultural Non-Point Source model on Windows. You download the USDA-ARS AGNPS package, stand in a CSV watershed folder, run AnnAGNPS.exe, and read the average-annual sediment and water files. GIS is not required for this path.

1. What this model does

AnnAGNPS is a continuous, daily, watershed-scale pollutant loading model. Landscape cells generate runoff, sediment, nitrogen, phosphorus, and organic carbon. Those loads move into reaches, and the reaches connect to an outlet. Sheet and rill erosion on a cell follow RUSLE relationships. Gully and channel processes are separate modules. The time step is daily; the files you will open first are average annual summaries.

The lab’s pinned engine is AnnAGNPS.exe version v6.00.a.024_2024.05.23 (64-bit), from the complete AGNPS 6.0 package.

2. Get the software

Download the complete self-extracting AGNPS package from the USDA-ARS National Sedimentation Laboratory. That archive is the one that includes the pollutant-loading engine, TopAGNPS, the Input Editor, STEAD, weather tools, and the manuals. The ARS software catalog entry is software id 524.

AGNPS software download ARS catalog (id 524)

On this host the extracted tree is already at C:\Grok\Models\installs\AnnAGNPS. If you are repeating the lab path, you can skip the download and use that folder.

4. Novice path: run the Ohio example

The example is a five-year continuous run (2006–2010, two initialization years) for a small agricultural watershed near Celina, Ohio. Precipitation in the output header is 38.492 inches per year. You will copy the CSV inputs into a fresh folder, drop the executable beside them, and run from that folder.

$src = "C:\Grok\Models\installs\AnnAGNPS\test_run\AGNPS_Watershed_Studies\OH_AGNPS_Example_Watershed\4_Editor_DataSets\CSV_Input_Files"
$run = "C:\Grok\Models\installs\AnnAGNPS\tutorial_run_20260913"
New-Item -ItemType Directory -Force -Path $run | Out-Null
Copy-Item "$src\AnnAGNPS.csv","$src\annagnps_master.csv" $run
foreach ($d in "climate","general","simulation","watershed") {
  Copy-Item "$src\$d" "$run\$d" -Recurse -Force
}
Copy-Item "C:\Grok\Models\installs\AnnAGNPS\AGNPS\PLModel\Execute\AnnAGNPS.exe" $run
Set-Location $run
.\AnnAGNPS.exe

On this host you can instead rerun the lab wrapper, which copies those inputs, executes the engine, asserts the numbers below, and rewrites the figure:

Model Input and Output

The diagram below is built from the verification folder on this host. Every file name in the picture is a real file from that run. Arrows show what the executable reads and what it writes.

Executable

AnnAGNPS.exe

This is the pollutant-loading engine. You copy it into the watershed folder and start it there. It reads AnnAGNPS.csv, then every table listed in the master file, and writes the average-annual load CSVs when the run finishes.

Input files

AnnAGNPS.csv

This is the first file the engine looks for in the current folder. It names the master table list, sets units and flags, and tells AnnAGNPS which CSV files to open before the first simulated day.

annagnps_master.csv

This is the table of contents for the run. Each row is one data section and the path to its CSV. If a path is wrong, the engine stops before it computes any loads.

climate/climate_daily.csv

This is daily weather for the watershed: rainfall and related climate values for each day of the simulation. Without this file the engine cannot compute runoff or erosion.

climate/climate_station.csv

This names the climate station and its location. It tells AnnAGNPS which weather record the daily file belongs to and how to treat missing days.

general/AnnAGNPS_Combined_Group_1_Soil_Data.csv

This is the soil map for the watershed. Each soil ID used on a cell is described here so the engine knows texture and related properties.

general/AnnAGNPS_Combined_Group_1_Soil_Layers_Data.csv

This is the layer-by-layer soil profile for each soil ID. Thickness, texture, and related properties by depth control how water infiltrates and how soil erodes on each cell.

general/AnnAGNPS_Riparian_Buffer_Data_Section_AgBuf.csv

This describes riparian buffers if any are in the watershed. Empty or placeholder rows still count as an input table the master file must name.

general/crop_growth.csv

This is crop growth parameters: how plants emerge, cover the ground, and use water. The engine reads it together with the management schedule so cover is not a guess.

general/cropdata.csv

This is the crop catalog. Each crop ID used in management points here for names and basic coefficients the engine needs before it can grow a canopy.

general/fertapp.csv

This is fertilizer applications tied to fields and dates. If no fertilizer is applied, the file can be nearly empty but must still exist. Keep the file beside the other inputs for this run.

general/fertref.csv

This is the fertilizer reference list: nutrient content of each fertilizer type named in the application table. The engine looks up those types here. Keep the file beside the other inputs for this run.

general/hydgeom.csv

This is hydraulic geometry for channels. It tells the engine how wide and deep reaches are so it can move water and sediment downstream. Keep the file beside the other inputs for this run.

general/manfield.csv

This lists management fields, the land units that share a schedule. Cells point at these fields so cropping is not retyped on every cell. Keep the file beside the other inputs for this run.

general/manoper.csv

This is the operation catalog: tillage, planting, harvest, and similar actions the schedule can call by name. Keep the file beside the other inputs for this run.

general/mansched.csv

This is the calendar of operations on each field. Dates and operation IDs drive cover and disturbance through the year. Keep the file beside the other inputs for this run.

general/non_crop.csv

This describes non-crop cover such as grass or forest if those land uses appear. Crop rows live in cropdata instead. Keep the file beside the other inputs for this run.

general/rocurve.csv

This is runoff curve numbers by cover and hydrologic condition. The engine uses them to turn rainfall into runoff on each cell. Keep the file beside the other inputs for this run.

general/Runoff_Curve_Number_Data_Input_Editor_v5.5_Format.csv

This is the same curve-number data in the Input Editor v5.5 layout. The master file names it so the editor and the engine stay in sync.

general/strip_crop.csv

This describes strip cropping if it is used. If the watershed has none, the file is still present as an empty or header-only table. Keep the file beside the other inputs for this run.

general/tiledat.csv

This describes tile drains. A tiny file means little or no tile drainage in this example, but the engine still opens it. Keep the file beside the other inputs for this run.

simulation/annaid.csv

This holds AnnAGNPS identification records for the simulation, including IDs the other tables refer to. Keep it with the rest of the simulation folder. Keep the file beside the other inputs for this run.

simulation/globfac.csv

This is global flags and factors for the whole run: unit choices, process switches, and multipliers that apply to every cell. Keep the file beside the other inputs for this run.

simulation/outopts_aa.csv

This turns average-annual output tables on or off. The sediment and water files you open after the run exist because this file asked for them.

simulation/outopts_global.csv

This is global output options. It controls logs and summary files that are not tied to a single cell. Keep the file beside the other inputs for this run.

simulation/outopts_tbl.csv

This controls table-style outputs such as gaging-station files. Leave it as the example set it unless you need extra tables. Keep the file beside the other inputs for this run.

simulation/sim_period.csv

This is the start date, end date, and length of the simulation. Wrong dates here are a common reason a first run looks empty. Keep the file beside the other inputs for this run.

watershed/AnnAGNPS_Cell_Data_Section.csv

This is the cell map: each landscape unit, its area, soil, field, and the reach it drains to. It is the spatial skeleton of the watershed.

watershed/AnnAGNPS_Ephemeral_Gully_Data_Section.csv

This describes ephemeral gullies. If the Ohio example includes gully rows, the engine can add that sediment source to the totals. Keep the file beside the other inputs for this run.

watershed/AnnAGNPS_Reach_Data_Section.csv

This is the channel network: each reach, how it connects, and where the outlet is. Cell loads enter here and move downstream. Keep the file beside the other inputs for this run.

watershed/AnnAGNPS_Wetland_Data_Section.csv

This describes wetlands in the network. Even a short file is a required table when the master list names it. Keep the file beside the other inputs for this run.

watershed/watershed_data.csv

This is watershed-level identification and area. It is a short header table the engine reads with the cell and reach files. Keep the file beside the other inputs for this run.

Output files

AnnAGNPS.log

This is the plain-language run log. It records start time, files opened, and whether the engine finished. Read it first if the window closes and you are not sure the run succeeded.

AnnAGNPS.nfm

This is a formatted notes file the engine writes while it reads inputs. It is not a load table. Use it only if you are tracing a read error.

AnnAGNPS.wrn

This is the warning file. It lists values the engine accepted but flagged, such as a soil or crop record near a limit. A warning is not the same as a failed run.

AnnAGNPS_AA.csv

This is the combined average-annual summary. It gathers water, sediment, and nutrient totals after the full period. Start here if you want one table instead of the split load files.

AnnAGNPS_AA_Nitrogen_load_(unit-area).csv

This table is average-annual nitrogen leaving each cell or reach, reported per unit area. Use it to see which parts of the watershed send the most nitrogen.

AnnAGNPS_AA_Organic_Carbon_load_(unit-area).csv

This table is average-annual organic carbon leaving each cell or reach, per unit area. It is a companion to the nitrogen and phosphorus files, not a substitute for sediment.

AnnAGNPS_AA_Phosphorus_load_(unit-area).csv

This table is average-annual phosphorus leaving each cell or reach, per unit area. Compare it with the sediment table when you care about nutrients bound to soil.

AnnAGNPS_AA_Sediment_load_(unit-area).csv

This is the main sediment table for this tutorial. Each row is a cell or reach. The Subtotal line for a reach is the number we check after a new run.

AnnAGNPS_AA_Sediment_load_by_source_(unit-area).csv

This splits sediment by source, such as sheet and rill versus gully. Use it after the total sediment table when you need to know where the soil came from.

AnnAGNPS_AA_Water_load_(unit-area).csv

This table is average-annual water yield by cell or reach, per unit area. The outlet row is the watershed water yield we check in the verification test.

AnnAGNPS_dbg.csv

This is a debug dump of internal values. It is not needed to confirm a first run. Open it only if a developer asked you to trace a specific cell.

AnnAGNPS_LOG_All.csv

This is the full machine-readable log in CSV form. It repeats status, information, and warning lines in one file for sorting in a spreadsheet. Keep the file beside the other inputs for this run.

AnnAGNPS_LOG_Execution_Status.csv

This tiny file is the run status in one or two rows. It is the fastest way to see that the engine reported a successful execution.

AnnAGNPS_LOG_Information.csv

This log lists informational messages, such as files opened and period length. It is not a load table. Use it to confirm the engine read the files you intended.

AnnAGNPS_LOG_Warning.csv

This log lists warnings in CSV rows. Scan it after a first success. Many first runs still succeed while this file is not empty. Keep the file beside the other inputs for this run.

AnnAGNPS_TBL_Gaging_Station_Data_Evt.csv

This table is event-scale gaging-station output the engine writes when that option is on. It is extra detail, not the average-annual sediment check. Keep the file beside the other inputs for this run.

AnnAGNPS_TBL_Gaging_Station_Data_Hyd.csv

This table is hydrologic gaging-station output. Use it only if you are matching a stream gauge. The tutorial check uses the average-annual water file instead.

7. After the first success

Once the engine has written those CSVs, you can open phosphorus and organic-carbon files the same way, or bring the average-annual tables into STEAD. Building a new watershed from a DEM is TopAGNPS plus the Input Editor; that is a different lesson. This one stops at a verified CLI run of the pollutant-loading model.
