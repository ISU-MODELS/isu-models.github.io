1. What this model does

APEX extends the field-scale EPIC model to a farm or small watershed. The landscape is cut into subareas. Each subarea has its own soil, slope, weather, and operations file. Water, sediment, nutrients, and pesticides move from those fields into channels and then to an outlet. The daily timestep also grows crops, applies fertilizer, and can run several erosion equations at once (USLE, MUSLE family, RUSLE, RUSLE2). You will open the annual watershed table first.

The lab’s pinned engine is apex1501.exe (APEX1501) from the WinAPEX 1501 program folder. For this example the driving erosion equation is MUST (theoretical MUSLE).

2. Get the software

Download APEX from the Texas A&M AgriLife EPIC/APEX software page. The Windows pieces you want are the APEX1501 executable and WinAPEX for APEX v.1501 (October 2016). Blackland Research and Extension Center in Temple, Texas, maintains the site. APEX-CUTE and QAPEX are later editors; you do not need them to finish this tutorial.

APEX software download WinAPEX 1501 Manuals

4. Novice path: run the west-Illinois hillslope

The example is a twenty-year continuous run (2001–2020) on a 30 m, 3% hillslope in west-central Illinois. Soil 114 is a fine sandy loam. Operations file 2 is barley, dryland, no-till. Mean precipitation in the output is 848.3 mm per year. You will copy the program-folder inputs into a fresh directory, drop the executable beside them, and run from that folder.

$src = "C:\Grok\Models\installs\APEX\WinApex\apexprog"
$run = "C:\Grok\Models\installs\APEX\tutorial_run_20260913"
New-Item -ItemType Directory -Force -Path $run | Out-Null
Get-ChildItem $src -File | Where-Object {
  $_.Extension -notin ".OUT",".ASA",".ACY",".AWS",".SUS",".WSS",".STR",".SCX",".MDB",".SOT",".LOG"
} | Copy-Item -Destination $run
Set-Location $run
.\apex1501.exe

Model Input and Output

The diagram below is built from the verification folder on this host. Every file name in the picture is a real file from that run. Arrows show what the executable reads and what it writes.

Executable

apex1501.exe

This is the APEX1501 engine. You start it in a folder that already holds APEXRUN.DAT and the tables APEXFILE.DAT names. It writes Winapex.* files in that same folder when the years finish.

APSUBLDM.exe

This is a companion builder that can assemble subarea loads. The tutorial run does not start it. The engine you execute for the first success is apex1501.exe.

Input files

114.sol

This is soil 114 in the compact .sol layout. The subarea file points at this soil for texture and layer properties on the west-Illinois field.

130.sol

This is another soil definition in .sol format sitting in the program folder. The example subarea does not have to use it. Keep the file beside the other inputs for this run.

134.OPS

This is another operations calendar shipped with the program folder. It is available if a subarea points at it. Keep the file beside the other inputs for this run.

2.OPS

This is an operations calendar: planting, tillage, and harvest dates for a dryland rotation. The example subarea uses this style of file. Keep the file beside the other inputs for this run.

25.WND

This is a wind record. APEXRUN.DAT can select this wind station. Wind affects evapotranspiration and some erosion calculations. Keep the file beside the other inputs for this run.

5.OPS

This is another operations calendar in the folder. Only the operations ID named in the subarea file is active for the run. Keep the file beside the other inputs for this run.

81.WP1

This is a monthly weather-parameter file for a station in the WP1 layout. It complements daily .DLY files when APEX needs monthly statistics. Keep the file beside the other inputs for this run.

A48309.DLY

A48309.DLY is a daily weather station file in the WinAPEX library: rainfall and temperature by day. WDLST.DAT lists it. APEXRUN.DAT chooses which station this run actually reads.

APEXCONT.DAT

This is the control card: start year, number of years, and many process switches, including which erosion equation to use. MUST in this example is set here.

APEXDIM.DAT

This sets array dimensions the engine was compiled to expect. Do not edit it on a first run. A mismatch can stop APEX before it writes annual tables.

APEXFILE.DAT

This is the map of table names. Each line is a file role such as soils or crops and the DAT file that fills that role.

APEXRUN.DAT

This names the run, how many years to simulate, and which weather and wind stations to use. APEX1501 reads it first. Wrong IDs here point the engine at the wrong climate files.

crop.dat

This is the crop catalog: growth parameters for every crop ID operations files can plant. Barley in this example is defined here. Keep the file beside the other inputs for this run.

fert.dat

This is the fertilizer catalog: nutrient content of each fertilizer type named in operations. Keep the file beside the other inputs for this run. Keep the file beside the other inputs for this run.

HERD.DAT

This is livestock herd data. A small file means little or no grazing in this example. Keep the file beside the other inputs for this run.

MLRN.DAT

This is a short miscellaneous record file. It is listed in APEXFILE.DAT so the engine can open it even when it is tiny. Keep the file beside the other inputs for this run.

OPSC.DAT

This is the operations schedule catalog. Field operations files such as 2.OPS draw their calendars from this system. Keep the file beside the other inputs for this run.

parms.dat

This is the parameter file of coefficients that are not crop- or soil-specific. Leave it as shipped for the first run. Keep the file beside the other inputs for this run.

pest.dat

This is the pesticide catalog. Even if this example applies little or no pesticide, APEX still opens the table. Keep the file beside the other inputs for this run.

PRINT.DAT

This chooses which output tables APEX writes. Annual watershed numbers in Winapex.AWS exist because this file asked for them. Keep the file beside the other inputs for this run.

PSOCOM.DAT

This is a reserved communication file. It can be empty. APEXFILE.DAT still names it so the engine can open the path. Keep the file beside the other inputs for this run.

RAINDT.HLY

This is hourly rainfall data WinAPEX can store. The verified tutorial path uses daily .DLY climate, not this hourly file, as the driver. Keep the file beside the other inputs for this run.

RFDTCOM.DAT

This is a rainfall-data communication stub. It is tiny. Daily rainfall for this run comes from the selected .DLY file. Keep the file beside the other inputs for this run.

RFDTLST.DAT

This lists optional rainfall-data files. The main daily series still come from the .DLY stations in WDLST.DAT. Keep the file beside the other inputs for this run.

SITE.DAT

This points at the site file, here WINAPEX.SIT. The site file holds latitude, weather assignment, and the subarea list for the farm. Keep the file beside the other inputs for this run.

SOIL.DAT

This is the soil catalog the subarea file indexes. Soil 114 in this example is described here by layer. Keep the file beside the other inputs for this run.

SOIL35K.DAT

This is a large extra soil library shipped with WinAPEX. The run may not index every soil in it. It sits in the folder because APEXFILE can point at a soil table.

SUBA.DAT

This points at the subarea file, here Winapex.sub. That file is the field map: area, slope, soil, and operations for each subarea. Keep the file beside the other inputs for this run.

till.dat

This is the tillage catalog. Each operation in an .OPS file points here for mixing depth and residue effects. Keep the file beside the other inputs for this run.

TR55.DAT

This holds TR-55 style runoff parameters APEX can use when that runoff option is on. Keep the file beside the other inputs for this run.

WDLST.DAT

This is the daily-weather station list. Each row names a TX*.DLY file, its coordinates, and a station title. APEXRUN.DAT picks which row this run uses.

Winapex.SIT

This is the site record for west-Illinois in this example: location, elevation, and which climate station the subareas use. Keep the file beside the other inputs for this run.

WINAPEX.SUB

This is the subarea table. Each row is one field with area, slope length, steepness, soil ID, and the operations file that field follows. Keep the file beside the other inputs for this run.

WIND.DAT

This is the wind station list. APEXRUN.DAT selects which wind record the run uses with the daily weather. Keep the file beside the other inputs for this run.

WPM1.DAT

This lists monthly weather parameters APEX can use when it needs generated climate. Daily .DLY files still supply the measured-style series this run prefers. Keep the file beside the other inputs for this run.

Output files

00000001.SOT

This is a soil-output table APEX writes for a subarea. It is created during the run. Use annual AWS numbers first, then this file for soil detail.

fort.102

This is a Fortran unit file APEX opened during the run. It is an internal scratch or echo file, not a table you need for the first check.

fort.108

This is another Fortran unit file written while APEX ran. Treat it as an engine side file, not as the annual sediment table. Keep the file beside the other inputs for this run.

fort.112

This is a small Fortran unit file from the run. You can ignore it until a developer asks for it. Keep the file beside the other inputs for this run.

fort.128

This is a small Fortran unit file from the run. It is not the watershed sediment output. Keep the file beside the other inputs for this run.

Winapex.ACY

This is annual crop yield output. Each year of the run can appear here with harvest numbers. It is not the sediment check. Keep the file beside the other inputs for this run.

Winapex.ASA

This is annual subarea output. It is a yearly field summary. Watershed sediment for the tutorial is in Winapex.AWS instead. Keep the file beside the other inputs for this run.

Winapex.AWS

This is the annual watershed table. Precipitation, water yield, and sediment yield YS by year live here. The verification test reads this file. Keep the file beside the other inputs for this run.

Winapex.OUT

This is the large text listing of the whole run. Search it when you need a value that is not in the short annual tables.

Winapex.SCX

This is additional annual or scenario text output APEX writes beside AWS. Open AWS first for the tutorial numbers. Keep the file beside the other inputs for this run.

Winapex.SUS

This is a summary output table. It is shorter than Winapex.OUT. Use it after AWS if you want extra annual totals. Keep the file beside the other inputs for this run.

Winapex.WSS

This is watershed summary output. It complements AWS. The first confirmation still uses the YS column in AWS. Keep the file beside the other inputs for this run.

run_stdout.txt

This is the console text captured when apex1501.exe ran. APEX often prints little here. Success is confirmed by the AWS file, not by this log alone.

7. After the first success

Once the engine has written those tables, you can open Winapex.ACY for barley yield and stress, or PRINT.DAT to change which variables are stored. Changing slope length or operations is an edit to Winapex.sub and OPSC.DAT; that is a different lesson. This one stops at a verified CLI run of APEX1501.
